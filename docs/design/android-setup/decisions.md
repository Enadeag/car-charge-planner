# Android set-up: decisions

Decisions about the Android app's first-run set-up, its home, the dashboard, and its Settings that the code alone does not explain. Newest last; each names the date and the issue or pull request that settled it. The 18 decisions of set-up's assumption check are on #314, the 11 of Settings' on #315 (comments of 2026-11-02), the 12 of the dashboard on #276 (2026-11-03); this list keeps the ones a later change is most likely to meet.

- **2026-11-02, #314: set-up is seven steps, without a navigation library.** Welcome, Location, Panels, Car, Charger, More (the house and weekly away on one page) and Check. Back on Welcome closes the app at once; on a later step it goes one step back and keeps what was entered. Back while the check runs cancels it; Back while Finish saves does nothing until the save ends, and the outcome then decides the screen.
- **2026-11-02, #314: Finish.** While saving, Finish is off and shows progress. Saved opens the dashboard without a message (the screen calls `shown(Saved)` itself). Failed keeps the English details and **Try again** on the Check step, in a live region. A settings file of a newer version opens the "update the app" screen. A value the engine refuses goes back to the first step with a refused value, with a line that says why.
- **2026-11-02, #314: the check runs on entering the Check step**, again on coming back to it, and again after the system ended the app. A failure shows **Check again** and the English details; Finish stays on.
- **2026-11-02, #314: the time zone.** It is chosen under **Advanced** from the list of zone ids only. A chosen place sets it; typed coordinates put it back to the phone's zone unless the owner chose one by hand. The phone's zone is read when it is used, not when the app starts. A zone loaded from a saved file counts as not chosen by hand, so in Settings (#315) typing coordinates also resets it, unless #315 decides otherwise.
- **2026-11-02, #314: the place search** runs on the Search button or the keyboard's Search key, never per keystroke, and sends the app's resolved language (`place_search_language`, `en` or `nl`). It shows at most 8 places; labels read alike only among those shown. The typed text is kept at most 100 characters and survives the system ending the app; the results do not.
- **2026-11-02, #314: a language change reaches the forms and the search without losing what was typed.** The view model is kept and told the new language in each `onCreate`; numbers typed before the change keep their decimal mark, which is read either way.
- **2026-11-02, #314: words.** The heading for an unusable settings file is "Settings file cannot be used"; the Dutch stays "Niet ingesteld", as `docs/translating.md` gives for Unusable config (#325 brings the desktop in line). In Dutch a weekly away period is "afwezigheid" throughout, its controls named with its number ("Afwezig tot, afwezigheid 2").
- **2026-11-02, #314: tests.** Screen tests run on Robolectric only. Compose's own accessibility checks are not used, as they find nothing there; the explicit checks (name, role, a drawn size of 48 dp, scrolling at font scale 2) replace them. What TalkBack really says is the maintainer's walk before a release.
- **2026-11-02, #315: Settings has seven pages, as the desktop, in its order:** Solar panels (every panel array), Location (coordinates, place search, time zone), Car and house, Charger, Forecast (providers and API keys), Away (weekly away periods) and Planning (levels, margin, tolerance, window, lead and charging hours). There is no About page, no App page and no "Set up again": that stays offered for an unusable settings file only.
- **2026-11-02, #315: save per page.** Each page has its own Save and stays open after saving. Back or Up with unsaved edits asks "Discard changes?", with Keep editing and Discard; nothing is lost silently. Back goes from a page to the list, then to the home, without a navigation library (`AppFlow`'s `Screen.Settings` with the page). The open page and the typed texts survive the system ending the app; the API keys and the problems do not.
- **2026-11-02, #315: after a save.** The home asks for the plan again on its return only when a save changed something stored (`Saves.changes`). A save's outcome that no screen showed yet shows on the home. A save that finds the settings file unusable, or of a newer version, leads to that file's screen, as `AppFlow` does at the start.
- **2026-11-02, #315: the API keys.** A masked field with Show and Hide, filled with the stored key; a key left untouched stays, an emptied one is removed. Keys that cannot be read get an inline note that asks to enter them again and save, and says the app asks again after a few minutes; a key left empty then stays as it is, and there is no retry button. Keys not stored get "the keys could not be stored, try again". While the Forecast page shows, its window is `FLAG_SECURE` (no screenshot, no preview among the recent apps), and its fields ask for no autofill.
- **2026-11-02, #315: the zone in Settings** (A2 of #314). Settings treats a stored zone as chosen by hand, so typed coordinates leave it alone; the owner changes it under Advanced or by choosing a place. Set-up keeps its rule.
- **2026-11-02, #315: the Forecast page** has a primary choice, a fallback choice that includes "None", and a section per provider with its settings. The primary and the fallback each have Check connection, on the typed, unsaved values and keys. Plain http to this phone is allowed as the engine allows it, and the check then shows the engine's English details. The place search on the Location page uses the stored primary provider, and says so when that provider has none.
- **2026-11-02, #315: panel arrays.** Remove acts at once. The last array's Remove is off, with the reason "A system needs at least one panel array", which TalkBack reads with the button. Arrays are named by position and name ("Array 2, east roof"); there is no reordering.
- **2026-11-02, #315: words.** The pages and actions have short phone words, the glossary's where a term is a domain term; they are in `docs/translating.md`.
- **2026-11-03, #315: icons and buttons.** Up is Material's `ArrowBack`, mirrored right to left, and the home's Settings is Material's gear, named "Settings", both from `material-icons-core` at the Compose BOM's version; `NOTICE` names it as an exception, and the Apache-2.0 text is in `android/legal/apache-2.0.txt` (the other AndroidX licence texts: #331). Every button is drawn at least 48 dp high, over Material's 40 dp, through the app's own button wrappers. A Settings save that worked says so in Material's snackbar; one that failed leaves the one line "Not saved." under the top app bar, read at once, and why, with the English details, at the top of the page that scrolls, so the line under the bar never crowds the page out at 200% or on a small screen (review round 2).
- **2026-11-03, #315: each screen's saved state ends with it.** Settings forgets its page, its question and its texts when it closes or its file turns out unusable, and set-up forgets its step and texts when the home opens and before a new set-up after an unusable file; the two share their forms' prefixes, so nothing of one shows in the other.
- **2026-11-03, #335: the dashboard's refresh.** Refresh is an icon in the top app bar, beside a pull down the page; both keep the plan in view while a new one is made, and do nothing while a question is pending. Coming back to the app asks again when the last answer, a plan or No forecast, arrived more than 15 minutes ago; a Settings change asks again at once and shows "Making the plan…".
- **2026-11-03, #335: what scrolls.** The notice after a save, the stale warning and the zone note scroll with the day's page and are not pinned, so at 200% on a small phone on its side the page keeps its room; the notice and the warning are drawn on the page in view only. The stale warning is a polite live region, read when the forecast turns stale and when the home opens with one; a refresh that stays stale says nothing new. The footer ends each day's page.
- **2026-11-03, #335: the top app bar's title wraps** without a line limit and the bar grows with it, on every screen, so nothing is cut off at 200%.
- **2026-11-03, #335: one model of a day.** `TodayPlan` is gone; a short text about today (#277) comes from the dashboard's first day.
- **2026-11-03, #336: the charts' own ground.** The solar chart and the battery bar are drawn on cards of a fixed ground, white in light and dark grey in dark, not the wallpaper's dynamic colours, so the contrast of the solar, grid and car colours on them holds whatever the wallpaper and is tested (lines and marks 3:1, words 4.5:1). This goes one step beyond decision 7 of #276, which fixed only the source colours (maintainer, during the review). Both drawings run left to right in every language, as their hours and levels do.
- **2026-11-03, #336: the chart and the battery bar for TalkBack.** Each is one node with the desktop's sentence (`CHART_SPOKEN`, `BATTERY_SPOKEN_*`) and the role of an image; the drawing, the legend, the levels and the marks' words are shown but not read apart. The chart's "same facts as text" is that sentence itself, shown under it.
- **2026-11-03, #336: the time axis** marks whole hours only ("15", or "3 PM" on a 12-hour clock), every 3 hours, else 6, else 12, so no two labels meet, and keeps each label within the plot as the desktop does; a narrow phone therefore shows fewer hours, also at the normal text size. Both drawings run left to right in every language.
- **2026-11-03, #337: the battery level** is entered in whole percent, 0 to 100, on today's Car battery card through **Update battery level**, in a Material dialog that opens empty, so the owner reads the car rather than accepting the assumed level. A decimal, text or a number outside 0 to 100 is refused with a line under the field, never clamped (the maintainer, on #337). Back or a tap beside the dialog with something typed asks "Discard changes?"; Cancel closes without asking. A refusal is read through a polite live region, as the field keeps the focus; the same refusal again is not read again. When the entry closes the focus goes back to Update, or to the title when Update is not shown. A saved level has the plan made again with the shown plan kept in view, even while a plan is being asked.
